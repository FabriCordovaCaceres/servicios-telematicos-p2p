## 1. Objetivo

Ejecutar pruebas funcionales sobre el prototipo P2P del proyecto Servicios Telemáticos para verificar el correcto funcionamiento de sus operaciones de gestión de tareas, la comunicación entre nodos y la sincronización de información.

Las pruebas permiten comprobar el cumplimiento funcional del requerimiento RQ13 dentro del alcance evaluado.

## 2. Descripción del prototipo

El prototipo P2P permite que dos nodos intercambien información mediante conexiones WebSocket.

Cada nodo dispone de una API REST para gestionar tareas y utiliza un mecanismo de sincronización para comunicar los cambios realizados a los demás nodos conectados.

Para las pruebas se utilizaron dos instancias del sistema:

| Nodo | Puerto | Dirección |
|---|---|---|
| Nodo 1 | 4001 | http://localhost:4001 |
| Nodo 2 | 4002 | http://localhost:4002 |

La comunicación entre nodos se realizó mediante el canal WebSocket `/p2p`.

El sistema implementa mecanismos de actualización por versiones y registros de eliminación (*tombstones*) para gestionar la sincronización de tareas.

## 3. Entorno de pruebas

Las pruebas se realizaron en un entorno local utilizando:

- Sistema operativo Windows.
- Visual Studio Code y PowerShell.
- Node.js y TypeScript.
- Express para la API REST.
- WebSocket para la comunicación P2P.
- Módulo `node:test` de Node.js para las pruebas automatizadas.

Se utilizaron dos procesos independientes, correspondientes a los nodos 4001 y 4002.

Antes de ejecutar las pruebas se comprobó que ambos nodos estaban activos y que las conexiones entre pares mostraban el estado `conectado`.

## 4. Metodología de pruebas

Se aplicaron pruebas funcionales manuales y automatizadas.

Primero se verificó el inicio de ambos nodos y su comunicación mediante WebSocket.

Posteriormente, se realizaron operaciones de creación, consulta, actualización y eliminación de tareas, comprobando que los cambios efectuados en un nodo se reflejaran en el otro.

También se ejecutaron solicitudes con datos incorrectos para verificar las respuestas de validación de la API REST.

Finalmente, se implementó un script automatizado para repetir las comprobaciones y registrar sus resultados.

## 8. Observaciones

Durante el inicio manual del Nodo 1 se presentaron mensajes temporales de conexión rechazada debido a que el Nodo 2 todavía no estaba iniciado.

Una vez que ambos nodos estuvieron disponibles, se estableció correctamente la comunicación bidireccional.

También se observó una falla temporal de conexión durante una consulta manual al Nodo 2. Al repetir la solicitud, la consulta se completó correctamente.

Estos incidentes no impidieron la ejecución exitosa de las pruebas funcionales automatizadas. No obstante, pueden considerarse como antecedentes para las pruebas específicas de fallos de comunicación de la Tarea T4.5.

## 9. Alcance y limitaciones

Las pruebas se ejecutaron en un entorno local con dos nodos P2P.

Se verificaron las operaciones REST, la conectividad entre pares y la propagación de tareas creadas, actualizadas y eliminadas.

Las comprobaciones automatizadas utilizaron esperas y consultas repetidas para verificar que los cambios se reflejaran en el nodo correspondiente.

Estas pruebas no constituyen una evaluación completa del rendimiento, la escalabilidad, la seguridad ni la tolerancia a fallos. Dichos aspectos serán tratados en otras tareas del Sprint 4.
